## 8. P2 backlog (do not block v0.5.0)

1. **Discarded errors in restore-point writes.** `internal/repair/repair.go`
   has 7 sites of `_, _ = rp.WriteJSON(...)` (lines 184, 190, 232, 237, 239,
   253, 263). If the write fails (disk full, permission), the manifest
   may not match what's actually on disk. Suggest: log the error to the
   incident ledger; do not change observable behaviour.
2. **Misleading action-ID prefixes.** `repair.go:361-365` IDs are
   `standard.location.create`, `standard.location.switch`,
   `standard.route.flush.1/2`, `standard.detectnewhardware`,
   `standard.ipconfig.<dev>`. These actions only execute when level is
   `standard-system-reset` or `deep`; the `standard.` prefix can mislead a
   reader (it almost misled this reviewer). Suggest: rename to
   `standard-system-reset.*` / `system-reset.*` for clarity. Pure renaming;
   no behaviour change.
3. **Support bundle does not directly include the `incidents/<ts>/` dir.**
   `internal/supportbundle/supportbundle.go:88-92` picks up
   `latest-session.json`, `latest-human-report.txt`,
   `latest-agent-dispatch.json` (which embed the orchestrator `Report` and
   therefore `IncidentReportPath`, `GemmaOverride*`, etc.), but the per-cycle
   artifacts (`supervisor-decision.json`, `repair-result.json`,
   `network-verify.json`, `terminal-ticket.json`, `restart-gate.json`,
   `postflight-comparator.json`, `network-rollback.json`) are NOT bundled
   directly. For offline triage, the support bundle gives the summary but
   not the per-cycle drill-down. Suggest for v0.5.1: include the latest
   incident dir alongside the latest session.
